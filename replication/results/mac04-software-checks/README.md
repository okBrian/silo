## I13 handoff · Erin and Brian

The first native target is the x86-64 Linux patched-kernel interface selected in I12. Start with the tested legacy floating-point/vector baseline. The continuation needs all general registers, RIP, RSP, RFLAGS, x87 data and environment, MXCSR, and XMM0–15. Pin both stacks to the same worker pthread and retain its FS/GS bases. Audit shared TLS before running high code, including `errno` and exception state. Confirm the kernel's frame layout and stack adjustment before choosing how the entry stub protects interrupted stack data, including the SysV red zone. Compile the handler entry and any pre-save helper for general registers only. If interruptible code can use AVX or other extended state, cover the OS-enabled components and size/alignment with CPUID and XCR0 before enabling that code. For the initial legacy-state window, constrain the actual instructions and linked callees that can run there. Verify CET/shadow-stack compatibility before enabling a build with it. [I12 runbook](../../uintr/README.md) · [Intel architecture manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html) · [GCC x86 handler rules](https://gcc.gnu.org/onlinedocs/gcc-16.1.0/gcc/x86-Attributes.html)

| Worker phase | Proposed native rule |
| --- | --- |
| Idle, setup, or entering low | Publish handler-visible state only after queue ownership and stack metadata are consistent. Keep switching disabled during transitions. |
| Low running | Record pending work on delivery. Begin capture only in an audited low window with protection depth zero. Leave a deferred notification pending through nested guards and reevaluate after cleanup. |
| Capturing low or running high | Keep the capture sequence noninterruptible. Run high service with nested switching disabled and its own transaction storage. Finish the current high request, including retries, before reevaluating the batch and starvation decisions. |
| Restoring low | Recheck queue work at the transition so concurrent publication cannot be stranded. Restore the complete low state and reenable delivery only when the low context can be interrupted again. An empty or duplicate notification can return without switching. |
| Teardown | Stop sender activity, disable delivery, and finish or safely unwind any suspended request before releasing the stack and channel. |

`ScopedNonPreemptible` and `WorkerContext` currently use ordinary thread-local or worker-owned state. The local tests invoke them synchronously. Native entry needs a handler-safe pending flag and a protocol that masks or serializes changes to handler-visible state, including the protection depth and stack transitions. Keep allocation, logging, locking and glibc `swapcontext` out of the handler. For the first Silo integration, start with audited windows in the logging-disabled protocol-2 Q2 path. The I08 audit covers explicit checkpoints. It leaves inter-checkpoint encoding, allocation, library calls and cleanup to audit before permitting arbitrary interruption across Q2. Preserve the paused snapshot's RCU guard. [I08 audit](../i08-silo-context/README.md)

The assembly fixture makes state live at a fixed `int3` instruction and compares it after Linux `SIGTRAP` return. The handler deliberately clobbers live registers. A separate run through the same fixture corrupts saved RAX and XMM0 to verify detection. Use the fixture's canaries for the native test with a sender handshake and a window that keeps them live. After I12 passes, require real delivery in that window, a high-context computation that clobbers the supported state, exact low continuation, and a second interrupt during each protected or transition phase. Reuse the nested-deferral test and exercise asynchronous arrivals around the depth and resume transitions on hardware. ## I14–I16 handoff · Brian with Erin on I14 and timing review

- I14 can attach a producer-side notification callback to the existing request driver. It runs after release publication and is separate from the ordinary idle-worker wake. Use the high queue as the source of work and the existing worker execution path for retry and terminal accounting. For native evidence, record admission, send attempts, handler entries and deferrals, actual switches and commits separately. Verify a high request executes during a paused Q2 and check the resumed result. [Request driver](../../../benchmarks/request_driver.cc)
- I15 has one callback per worker in each admission pass that published high work. Fixed routing, bounded local queues and the global FIFO remain the admission rules. The deterministic driver test fills both local queues and delivers the remainder in a second pass, including a retry and duplicate idle wakes. The native integration still needs tests around delivery delay, coalescing, queue drain and low resumption. [Driver tests](../../tests/request_driver_test.cc)
- I16 has a worker-owned cycle-budget calculation with injected timestamps and a strict integer percentage comparison. Start it once per low request, carry it across low retries, and charge an entire high request including retries before applying the return-to-low decision. Admission needs a synchronized snapshot of the same budget and comparable serialized cycle readings across pinned CPUs. The threshold can be exceeded during a high request. Native overload tests must record both low CPU service and Q2 commits. [Budget](../../../benchmarks/starvation_budget.h) · [Policy contract](../../docs/experiment-contract.md)
