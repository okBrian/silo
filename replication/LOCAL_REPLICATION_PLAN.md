## MAC-09 — Build and validate the Linux-signal preemption test backend

1. Implement a separately named opt-in backend inside the x86-64 Linux/glibc guest. Use asynchronous signal delivery to a designated worker as the local notification transport. 2. Define the supported registers/extended state, signal mask and alternate-stack rules, handler-safe pending state, and capture/high-service/restore transitions. Audit shared TLS and interrupted unsafe operations. Keep allocation, logging, locking and ordinary glibc context-switch calls out of the signal handler; use an audited capture/return design and safe execution windows. Record any unsupported state or restricted windows.
3. First validate standalone asynchronous interruption, exact continuation and deliberate state-corruption detection. Cover nested protection, repeated/coalesced signals, transition arrivals, exceptions/cleanup where supported, and bounded teardown. A flag observed later at a checkpoint is a deferral test, not proof of an asynchronous context switch.
4. Integrate with Silo's isolated low/high transaction state and paused snapshot lifetime. Demonstrate an arriving short executing while Q2 is suspended, followed by the same Q2 attempt resuming with its expected checksum. Exercise retries, abort cleanup and shutdown, then rerun MAC-07 and MAC-08 integration cases and the existing engine/driver regressions.

**Complete locally when** the saved standalone and Silo integration checks establish the claimed asynchronous behavior for the documented windows/state and reproduce the expected Q2 result. Label all results **Linux-signal backend in emulated Linux**. Signal-frame preservation, delivery semantics and overhead differ from UINTR; native entry/return preservation and hardware performance remain unvalidated. This is new runtime work and remains planned until implementation and tests actually pass.
